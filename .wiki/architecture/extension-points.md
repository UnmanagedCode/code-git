# Extension points

How later cards plug in without editing each other's files. The table of what to create and where to register: `docs/architecture.md` → Extension points. The decisions:

- **Registries are explicit lists, not self-registration.** `PANELS` (`frontend/src/shell/panels.ts`), `ACTIONS` (`frontend/src/shell/menus.ts`) and the `buildRegistry` list (`src/git/ops/index.js`) each import their entries. A feature module calling `registerPanel()` at import time would create an import cycle with the registry module (TDZ at load). A feature adds one import + one list entry; parallel cards conflict only on adjacent lines.
- **Ops, not routes.** A new git capability is an op file; `POST api/ops/:name` already handles target validation, cancel wiring and activity. Add a route file only for something that is not a git op.
- **`cancellable` is resolved once at load** (`buildRegistry`); the route and the activity log read the frozen definition. Default read → true, write → false; a non-boolean throws at load.
- **Write lock is per project, not per checkout** (`src/git/locks.js`): worktrees share refs and objects, so two writes on different worktrees of one project still serialize.
- **On-demand panels** (`PanelDef.onDemand`, `state/shownPanel.ts`): a panel such as the diff takes over its slot for one tab while `showPanel` names it, instead of each feature hand-rolling "replace the graph". `Slot` in `Shell.tsx` is the only reader; the shown id is per `tabKey`, pruned when the tab closes, and not persisted (a reload shows the graph).
- **Ops get `{target}` as `run`'s third argument** for naming output after the checkout (`diff.patch` filenames); git still goes only through the bound `git`.
- **Per-checkout UI state** goes in a feature's own store keyed by `tabKey`; there is no central `RepoState` to edit.
- **Context-menu contexts** are free strings: `'tab'`, the diff's `'diff-file'` (a diff's file list row), the Changes panel's `'workdir-file'` (ctx `{tab, file, section}`) and the graph's (`CONTEXT` in `frontend/src/features/graph/contexts.ts`, with each ctx type; table in `docs/architecture.md` → Extension points). A later card adds write actions by appending a `MenuAction` list to `ACTIONS` with an `order` from the convention there — never by editing the graph's files.
- **`<ActionMenuItems>` renders inside a `DropdownMenuContent`**; a tab's menu is a controlled DropdownMenu opened by its ⋮ trigger or by `onContextMenu` (cc ships no context-menu component). For a menu at the pointer, `openContextMenu({host, …})` + `<ContextMenuHost host>`: one host per panel, named, because a menu opened from inside a modal dialog (the refs panel on a phone) must render inside that dialog's layer to be usable.
- **The anchor moves before the menu opens**: `ContextMenuHost` sets the 1×1 anchor's position in a layout effect and opens on the next render, so Radix places the menu from the new position.
- **The graph hands the diff viewer stores, not callbacks**: `graphSelectionStore` (selection, top to bottom) and `fileIntentStore` (`seq` increases per click). Neither side imports the other's components.
- **`openWorkingTree(target, {amend?})` is the commit box's entry point**, not "show the right slot": below `lg` the slot is hidden (display none, still mounted), so the call opens the Changes dialog instead, and a focus request names which instance (slot or dialog) takes the focus — both may be mounted at once.
- **One `ConfirmHost`**, mounted by the Changes panel (always mounted while a tab is open: the right slot is hidden by CSS, not unmounted). `confirm()` resolves false when another confirmation replaces a pending one.
