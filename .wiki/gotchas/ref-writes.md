# Gotcha: writing refs

The branch / tag / HEAD ops (`src/git/ops/branch.js`, `tag.js`, `head.js`, shared helpers in `src/git/refs/`). Rules and tables: `docs/refs.md`.

- **Where a branch is checked out: `for-each-ref --format=%(worktreepath)`** (git ≥ 2.23), one command for every branch (`readHeads`). `worktree list -z` needs 2.36 and parses per worktree; the graph uses it for labels, the write ops do not. A branch being rebased in another worktree has an empty `%(worktreepath)` there (that worktree is detached), so fast-forward and force-move do not see it; `branch -d/-m` still get git's own check.
- **A symbolic ref under `refs/heads` slips past both guards**: `%(objectname)` is its target's and `%(worktreepath)` is empty, and `update-ref`/`switch` follow it to the target. `readHeads` reads `%(symref)`; writes refuse one as their subject (`SYMBOLIC_REF`), `update-ref` runs `--no-deref`, and `branch -d alias` deletes only the alias. A **dangling** symbolic ref (target missing) is not even listed by `for-each-ref`, yet `git branch a` / `git tag a` follow it and create the target — `refs/heads/a → refs/tags/t` makes `branch a` write `refs/tags/t`. Pushes have the same hole one level out: `git push origin :refs/heads/b` (and a successful branch push) updates `refs/remotes/origin/b` here and follows it if symbolic — an alias to a checked-out cc branch deleted that branch — so `push()` checks each branch destination's tracking ref first. *Which* ref git writes comes from the remote's configured fetch refspecs (`remote_find_tracking`), not `refs/remotes/<r>/<b>`: `+refs/heads/*:refs/remotes/other/*` makes it `other/<b>`, so `tracking.js` maps through `git config --get-all remote.<r>.fetch` and fails closed on shapes it does not parse. `-c remote.<r>.fetch=` cannot neutralise it (it appends). **Negative refspecs protect only an exact mapping** (git 2.55): `^refs/heads/main` stops `+refs/heads/main:refs/heads/victim` from moving `victim`, but `^refs/heads/b` does not stop a wildcard `+refs/heads/*:refs/remotes/origin/*` (or `…:refs/heads/mirror/*`) from moving or deleting — through a symbolic ref too — the ref it maps `b` to. The mapping applies no negative refspec: it over-refuses the exact case rather than hide the wildcard one. **A url is a non-empty value after the last empty one** (`url=''` clears the list; `pushurl` does not count): without one, git takes refspecs from a legacy `.git/remotes/<name>` or `.git/branches/<name>` file, so that case is refused only when such a file exists (`rev-parse --git-path` + `hash-object --no-filters`, which fails for a missing or unreadable path, as git's own reader does); a push-only remote with no file maps through config. `symbolic-ref -q <exact ref>` exits 0 for it (1 for a plain or missing ref): create, rename and delete ask it (`assertNoSymref`).
- **"This checkout" is `symbolic-ref -q HEAD`, never a path compare** (`ownHead`): paths differ between cc's record, git's and the System's view (symlinks, containers).
- **`branch -d a b c` deletes what it can and exits 1** for the rest. Re-read the heads afterwards (`branch.delete`): gone = deleted; still there with `'<name>' is not fully merged` in stderr = `notMerged`; anything else is a real failure.
- **Fast-forward and force-move of a branch that is not checked out use `update-ref <ref> <new> <old>`**: the compare-and-swap refuses ("but expected") if the ref moved since the UI read it → `REF_MOVED`. Never `branch -f`, which has no old value.
- **`push --porcelain` exits 1 when any ref is rejected and 128 when nothing ran**, so `okExit: [0, 1, 128]` and the outcome comes from the `<flag>\t<from>:<to>\t<summary>` lines. No ref line + non-zero exit = the push failed as a whole (auth, unreachable, a pre-push hook) — classify stderr (`classifyRemoteFailure`), else `GIT_FAILED` with it.
- **`git stash create` is the hard-reset snapshot**: it writes a dangling commit of the tracked changes without touching the stash list or the worktree; empty output = nothing to save. `git stash apply --index <oid>` restores it exactly until gc — `stash create` records the index as a parent, and without `--index` everything comes back unstaged. Untracked files are never in it — and `reset --hard` never touches them either.
- **An empty cherry-pick leaves `CHERRY_PICK_HEAD` behind** (exit 1, "The previous cherry-pick is now empty"), which would block the next operation: `head.cherryPick` aborts it and refuses `PICK_EMPTY`. An empty revert exits 1 without `REVERT_HEAD`. Local changes in the way make both exit **128** ("would be overwritten by merge"), not 1.
- **A tag's undo needs the unpeeled object**: `%(objectname)` of `refs/tags/x` is the tag object for an annotated tag; `update-ref refs/tags/x <that>` brings back the message. The commit (`^{}`) would restore a lightweight tag instead.
- **`tag -a -F -` strips `#` lines by default**: `--cleanup=verbatim` keeps the message byte for byte (and adds no trailing newline).
- **`switch -c <b> <start>` with conflicting local changes creates no branch**: git checks the tree first. `switch` without `--no-guess` would invent a tracking branch from a remote name: always pass it.
- **`for-each-ref refs/tags/v1` also matches `refs/tags/v1/x`**: filter to exact names (`refObjects`).
