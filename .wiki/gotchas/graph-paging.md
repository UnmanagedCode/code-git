# Gotcha: paging the commit graph

Reference: `docs/graph.md` (behaviour), `docs/protocol.md` → Graph ops (argv). What bites:

- **Page with `--skip` over a frozen tip set, not from a cursor commit.** `--topo-order` is only stable for a fixed set of starting points: "the next 500 after commit X" changes meaning when a ref moves, and a cursor commit can sit in the middle of a lane. `graph.page` takes the tips explicitly (on stdin) and a skip, so page N of a snapshot is always the same rows; the UI replaces the whole snapshot when the tips move (`refreshGraph` in `frontend/src/state/graph.ts`).
- **Tips go on stdin, never argv.** Thousands of refs would pass `ARG_MAX`, and a stdin line starting with `-` would be read as a flag (`--not`) by `rev-list --stdin` — which is why every oid is `assertOid` (full lowercase hex) first.
- **`--shortstat` is slow** (a diff per commit: on the order of a second per 500 commits on a large repo), so the Changes column asks `graph.stats` for the visible rows only, after scrolling settles. A merge has no shortstat (`null`); a non-merge without a stat line changed nothing. `--root` is explicit because `log.showRoot` is configurable.
- **`log.showSignature` would run gpg per commit** and print into the records: every log-family command passes `--no-show-signature`. `%G?` asks for verification regardless — only `graph.commit` uses it (one commit), and tests pin that the page and search argv never contain `%G`. Same family: `--no-ext-diff --no-textconv`, since `diff.external` and textconv drivers are programs.
- **`git worktree list --porcelain -z` needs git 2.36.** Its failure is caught and returned as `worktreesError` (labels degrade); every other `graph.refs` failure fails the op. Without `-z`, paths with newlines would break the grammar.
- **`--author` ANDs with `--grep`.** Commit search runs them as separate commands and unions the oids. Each pattern is inside one `--grep=<q>` / `--author=<q>` argv element (so `--output=/x` stays a pattern) with `-F` (no regex, so no ReDoS) and `-i`; control characters are refused because a newline would be a second pattern.
- **`rev-parse --disambiguate=<prefix>` returns any object type**, exits 0 with no output when nothing matches and 128 on a prefix git cannot take: filter the candidates with `cat-file --batch-check='%(objectname) %(objecttype)'`. A SHA match need not be reachable from the tips; the UI says "not in the visible graph" after paging to the end.
- **Records are fields by NUL, the last by newline** (`parseRecords` in `src/git/parse/graph.js`), read by counting NULs so a newline inside a crafted ident cannot split a record; the last field is `%s` (a joined subject) or a refname, which never hold one. The commit body (`%b`) is the last field of `graph.commit`'s single record.
- **`%(*objectname)` peels differently by git version**: newer git peels a tag of a tag to the commit, older git one level (then the ref's `oid` is null and it is not graphed). Tests accept either.
- **`--end-of-options` needs git 2.24**, so `graph.commit` does not pass it: its only revisions are oids already checked as full hex (`assertOid`), which cannot be read as options. Details then work from git 2.22 (`docs/graph.md` → Git versions).
- **A file list can pass the exec output cap** on a huge commit. `graph.commit` runs metadata and `diff-tree` as separate commands; the second failing returns `files: null` + `filesError` (the UI says "Too many changes to list") instead of losing the metadata. A cancel still cancels the op.
