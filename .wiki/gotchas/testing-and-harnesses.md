# Gotcha: tests and harnesses

- **The fake cc runs real git** (`tests/_fakeCc.js`). It validates the exec body like cc and spawns git in the project's directory, so runner/op tests exercise real porcelain output, hooks and exit codes. A `system: 'docker'` project in the fake still runs locally — the point is that code-git addresses it by name alone.
- **Hermetic git env** (`hermeticEnv` in `tests/_git.js`): temp `HOME`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL` = a temp file with identity, `commit.gpgsign=false`, `init.defaultBranch=main`, `protocol.file.allow=always`. Without it, a developer's own config (signing, hooks path, default branch) leaks in.
- **`protocol.file.allow=always` lives only in fixtures and that global config** ("the System user opted in"): per fixture command via `-c` (`fixtureGit` in `tests/_submodules.js`), never in product argv/env (`submodule-hostile.test.js` scans every exec). `subWorld({allowFile: false})` rewrites the global config without it to prove git's default refuses.
- **`execHook` returning `'hold'`** parks a request until `release()`; `nextHeld()` waits for it without sleeping. Use it for lock-ordering, cancel and disconnect tests. `held.disconnected` tells a client abort from a normal answer.
- **`fakeCc` sets `process.env.CONDUCTOR_URL`** and restores it on `close()`; `node --test` runs each file in its own process, so files don't collide.
- **UI stores are module singletons**: every new store needs a reset in `frontend/src/test/setup.ts`, or state leaks between tests.
- **Stop the graph's watchers before resetting the prefs** (`resetGraph()` before `resetGraphPrefs()` in `test/setup.ts`): a live watcher notified by the prefs reset would re-read prefs from storage not yet cleared and leak the previous test's hides into the next one.
- **The focus throttle reads an injectable clock**: `setGraphClock(() => now)` in `state/graph.ts` (reset by `resetGraph`); tests advance `now` instead of sleeping. Focus refreshes only the active tab, so open the tab with `dispatchTabs` first.
- **Async work outliving its test hits the real `fetch`**: after a test `vi.unstubAllGlobals()` restores happy-dom's fetch, and a refresh still paging would connect to `localhost:3000` (`ECONNREFUSED` noise, or worse, a later test's stub). `resetGraph` bumps an epoch that every graph load checks before its next request.
- **`vi.mock('@/shell/menus')` is too late on its own**: `test/setup.ts` imports `ContextMenuHost` (and so the real registry) before the test file runs. Mock, then `vi.resetModules()` and import the modules under test dynamically (`ActionMenu.test.tsx`, `drag.test.tsx`).
- **happy-dom has no layout**: `scrollTop` is stored unclamped and `clientHeight` is 0, so virtual-list tests define `clientHeight` on the element and fire `scroll`; `matchMedia('(min-width: 64rem)')` matches (the window is 1024 px wide), so panels render in their wide layout.
- **happy-dom loads no external stylesheets or iframes** (`enableCSSFileLoading` / `enableIframePageLoading` are off by default): a test that needs either must enable them in `environmentOptions.happyDOM.settings` in `frontend/vitest.config.ts`.
- **In happy-dom, Radix menus open with `userEvent.click`** on the trigger; a right-click is `fireEvent.contextMenu`. Testing Library's ByRole `name` string is already exact (no `exact` option there); Playwright's `getByRole` name *is* substring by default — pass `exact: true`.
- **To send a path like `/api/repos/%2E%2E/x` unnormalised, use `http.get({hostname, port, path})`.** `fetch` and `http.get(urlString)` parse a WHATWG URL and collapse `%2E%2E` client-side, so the server never sees it.
- **The colour guard exempts `components/ui/`** (copied cc components keep `bg-black/40`, `text-white`); a test feeds the patterns known-bad and known-good classes so the guard cannot silently stop matching.
- **Harnesses need `CC_PROJECTS_ROOT`** (exported by cc into workers; export it yourself elsewhere) to find code-playwright and code-mutant. Never search for them.
- **`harness/playwright/live.mjs` and `live-graph.mjs` are read-only by contract**: only the picker, `repo.summary` and the `graph.*` reads (`live-graph.mjs` fails if any other op is called). Never Rescan/Enable the plugin in a live cc from a worker; find the live cc's URL from the session's `--mcp-config`, never by port scan (scratch ccs listen too). See `harness/playwright/README.md`.
- **One read of `/api/activity` does not see a whole op run**: an entry is `running` until its command closes, and an op's later commands (`remote.list` runs `git remote`, then `config --get-regexp`) may not have opened yet. Two tabs on one project (its main checkout and a worktree) can each start a `remote.list` (the remotes store dedupes by project, the graph state by tabKey). `live.mjs` counts, per `target.project` of the request body, the `remote.list` requests the page sent, answered and failed, and waits until every sent one is answered or failed (a failed one fails the run) and no activity entry with `op === 'remote.list'` and that `target.project` is `running`. Read the counts *before* the activity snapshot: a run answered after the snapshot would count as answered without its entries in it. For a **write**, `GET api/activity`'s `runs` says whether its op run is still open (`running` between its commands too); reads such as `remote.list` open no run, so this wait stays entry-based.
- **`live.mjs` derives its default checkouts from cc at run time**: worktrees are created and removed per task, so a fixed list goes stale. A named checkout cc does not list is an error, not a skip.
- **Playwright's `filter({hasText})` matches `textContent`**, which joins elements with no separator: an activity row reads `exit 1git --no-pager…`, so `/exit 1\b/` never matches — use `/exit 1(?!\d)/`. `waitFor()` on a row scrolled out of its region can also time out; poll `count()`.
- **Every Shell render mounts the Submodules panel** (left slot), which calls `submodule.list`: a Shell-level test world must stub it (`workdirWorld`, `stubGraph` and `Shell.boundary.test.tsx` do), or the panel adds an alert.
- **Playwright's `getByRole` name and `getByText` are substring matches**: the graph repeats the header's texts ("1 staged" on a WIP row, "Refresh graph"), so scope to a landmark (`getByRole('list', {name: 'Changes'})`) or pass `exact: true`.
- **Mutation harness isolation is `copy`**: tests never run git inside the project tree (only in temp repos), so the copy's missing `.git` doesn't matter.
- **Every Shell render now mounts the Changes panel**, which lists through `diff.files` and reads `commit.*`: a test stubbing one `Response` object for every `diff.files` call must `clone()` it (a body reads once), and assertions about the diff's alerts or first list request must be scoped to the Diff region. `test/workdirWorld.ts` stubs the panel's routes.
- **Playwright names match by substring**: the panel's reload button is "Reload changes" so the header's `getByRole('button', {name: 'Refresh'})` stays unique.
- **Two op worlds in one test talk to the last fake cc**: each `fakeCc` takes over `process.env.CONDUCTOR_URL`, which every op reads per request. A differential test (stash vs stage the same selection) creates and uses one world at a time.
- **The diff ignores Esc while focus is in a form field** (its key handler skips typing targets, radios included), and a dialog that closes after its trigger unmounted (a selection bar's button) leaves focus on `body`: harness steps close the diff with **Close diff**.
- **A sonner toast's removal timer outlives its test file**: a dismissed toast unmounts itself 200 ms later (`TIME_BEFORE_UNMOUNT`) through a `setTimeout` the Toaster's unmount does not clear; fired after the file's environment is gone, it is an unhandled "window is not defined" (seen only under full-suite load). `test/setup.ts` waits it out in `afterAll` for files that showed a toast.
- **sonner lists the newest toast first and removes each after its lifetime** (4 s, `TOAST_LIFETIME` in sonner): an earlier identical toast may or may not still be on screen when the next one appears, so a harness never counts or indexes matches (`nth(n)` waits forever once the earlier one expired). `harness/playwright/toasts.mjs` › `toasted` marks the toasts on screen before the action (`data-seen`) and waits for an unmarked one; each tracked op makes a new toast element, so the new one is never marked.
- **A banner title built from two fetches**: the operation banner's state comes from `commit.state`, its "onto origin/main" from the graph's refs (`commitLabel`), a later `graph.refs` request; until that lands the title names the short oid. Wait for the full text (`waitFor`), never a one-shot `count()` after the banner appears; `operations.mjs` holds `graph.refs` until its wait has started.
- **A timed-out Vitest test leaks its async steps into the next test**: Vitest cannot cancel them, so they act on the next test's DOM through `screen` and the store singletons (a stale stash save posts "wip" to a later test's stub). Guard acting steps with the test context's `signal` (aborted on that test's timeout), as `stash/dialogs.test.tsx` › `steps` does; a step already in flight still finishes.
- **The UI suite's timeout is one value set from a measured loaded worst case**, not a per-test number: on a loaded host a broad tail of tests slows down while no test is slow on its own. The basis is the comment beside `testTimeout` in `frontend/vitest.config.ts`.
- **Complexity tests measure thread CPU time** (`process.threadCpuUsage()`), never wall time: a loaded host deschedules the thread without charging it. Size the input so the cheapest quadratic variant costs seconds and set the bound between it and the linear cost (`tests/mask.test.js`).
- **A run's `ended` waits for every git call, lock wait included**: a write's sibling commands queue on the per-command project lock, so after a `Promise.all` rejects one may not have opened its entry yet. The route counts calls (`run.track`), not live entries; `tests/routes.test.js` holds such a queued sibling. The run ring likewise drops only ended runs: evicting a running one would make `writeRunning` read the project idle mid-write.
- **Settled-read checks need a deterministic window**: `remotes.mjs` holds only the pull's `rebase` (`execHook` on `argv.includes('rebase')`) and waits for the activity row `remote.pull running` before checking — by then every earlier command's close has reached the UI, so a pre-fix watcher read would already have started. `settled.mjs` records reads per in-flight write request.
