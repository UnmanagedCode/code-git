# Gotcha: talking to remotes

Fetch, pull, push and the remote config ops (`src/git/ops/remote.js`, helpers in `src/git/remote/`). Rules and tables: `docs/remotes.md`; the hostile-config table: `docs/architecture.md`.

- **`protocol.<name>.allow` beats `protocol.allow`, and `-c` beats every config file**, so `NET_CONFIG` (`-c protocol.ext.allow=never -c protocol.fd.allow=never`) wins over a repo's `protocol.allow=always`, `protocol.ext.allow=always` and an `insteadOf` rewriting a url to `ext::sh -c …` (git: "transport 'ext' not allowed"). Only the environment's `GIT_ALLOW_PROTOCOL` overrides it (verified with git 2.55) — the System's, not the repo's, and setting it ourselves would restrict every transport (an empty value allows none).
- **A 403 is "unable to access … returned error: 403"**: the unreachable pattern `unable to access` also matches it, so the credential rules are checked first (`classifyRemoteFailure`'s order). Likewise a credential helper's rejected credentials print git's `could not read Username … terminal prompts disabled` line *and* `Authentication failed`: credentials before prompt.
- **git 2.48+ fetch creates `refs/remotes/<r>/HEAD` itself** (`remote.<r>.followRemoteHEAD`, default `create`): a symbolic ref the first fetch adds. It is the one symbolic tracking ref allowed (`isHeadAlias`: the destination pattern with `HEAD` for `*`, pointing into the same pattern) and never reported as "resolved".
- **git 2.55's fetch skips a symbolic tracking ref** (live or dangling: neither it nor its target is written, silently), unlike push, which writes through one. The live-symref refusal before a fetch does not rely on that; a dangling one still comes to life when the fetch creates its target by other means — e.g. `origin/new → refs/tags/v9` and the fetch follows tag `v9` — which is what `symrefsResolved` reports. A live one is refused by the next fetch.
- **`--no-prune-tags` and an explicit `--prune`/`--no-prune` on every fetch**: `fetch.prune`, `fetch.pruneTags` and `remote.<r>.prune(Tags)` would otherwise delete tracking refs or local tags with no confirmation.
- **`rebase.updateRefs=true` moves other branches**: every local branch pointing at a commit in the rebased range is rewritten with it (a `code-conductor/*` one included). Every rebase pins it off, with `rebase.autoStash` and `rebase.autoSquash`.
- **Pull is not `git pull`**: `pull.rebase=interactive`, `pull.ff=only` and friends are never read; the pull fetches through `fetchRemote` and integrates an explicit oid (never `FETCH_HEAD`, which a cancelled or multi-remote fetch can leave partial).
- **`git merge` exits 2 when local changes would be overwritten, 1 on conflicts**; the merge pull accepts 0 and 1, so `guardOverwrite` (which acts on a `GIT_FAILED`) still turns exit 2 into `CHECKOUT_CONFLICT`. `git rebase` exits 1 for conflicts *and* for untracked files in the way ("could not detach HEAD"): tell them apart by the unmerged files, and abort either way (`rebase --abort` exits 128 when nothing is in progress).
- **`--force-with-lease=<ref>:` with an empty expect means "must not exist on the remote"**; with no `:<expect>` git would lease against the tracking ref, which a background fetch may have moved. `remote.push` always passes the oid the UI showed, never `--force` or a `+` refspec. A stale lease is rejected as `stale info`.
- **`ls-remote <remote> refs/heads/x` matches path tails**: `refs/heads/a/refs/heads/x` matches too. `remote.peek` keeps the exact name.
- **`git remote` lists a remote only from config keys**: a remote defined only by a legacy `.git/remotes/<name>` file is not listed until some `remote.<name>.*` key exists. `git remote remove` deletes only `refs/remotes/` refs its refspecs map (never `refs/heads`, even with a mirror refspec) and keeps a ref another remote also maps; it clears `branch.<b>.remote`/`.merge` from config whether or not the branch exists.
- **`git remote set-url <name> <url>` without an old url replaces the single value**, and fails ("multiple values") on a list: `remote.edit` refuses a multi-valued list before running it.
