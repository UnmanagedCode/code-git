# Gotcha: git-flow, git-lfs and hooks

## Git-flow

- **The production key is `gitflow.branch.master`** whatever the branch is called (nvie's and AVH's name); the version-tag key reads back lowercased, `gitflow.prefix.versiontag`. `config -z --get-regexp` prints `key\nvalue\0`, and a key with no `=` prints `key\0` with no newline (an empty value here: `readFlowConfig`).
- **`merge-tree --write-tree` needs git ≥ 2.38**. With `-z --name-only --no-messages`, exit 0 is clean, exit 1 conflicted; stdout is the tree id, then the conflicted paths, each NUL-terminated (`preflight` in `src/git/ops/flow.js` drops the first field). It writes nothing to refs, HEAD or the index: the preflight that makes `FLOW_CONFLICT` atomic.
- **Develop merges the flow branch, not the tag** (nvie; AVH merges the tag). That is what lets both merges be preflighted before the first write.
- **`switch -c <name> --end-of-options <oid>`**: the new branch's name is `-c`'s value, never parsed as an option, so it sits before `--end-of-options` (as `branch.create`). The argv test allows exactly that.
- **A failing `pre-merge-commit` hook makes `git merge` exit 1 with no unmerged path** and leaves `MERGE_HEAD` and the staged result. `integrate.merge` accepts exit 1 (a merge's conflict exit), so the command's activity entry reads `ok` while the op refuses `GIT_FAILED` (in `flow.finish`: `FLOW_INCOMPLETE`'s cause); look entries up by argv, not by `failed`.

## git-lfs

- **Every git-lfs command but `version` may write.** `git lfs track` installs git-lfs's four hooks and creates `.git/lfs/tmp` even to list (`--json`, `--dry-run`); `ls-files` creates `.git/lfs/objects` once there are LFS files, and hooks when the filter is configured. So `lfs.status` never runs them: it parses the root `.gitattributes` itself (`parseLfsAttributes`, git's attr parser rules) and the file list is `lfs.files`, a journal-neutral write the user asks for.
- **git runs git-lfs too**: with LFS files and the filter configured, a plain `git status` runs the clean filter, which installs the hooks and creates `.git/lfs`. A harness asserting "nothing written" after opening a tab fails for that reason, not because of an LFS op; `tests/ops-lfs.test.js` proves `lfs.status` alone leaves `.git` byte-identical.
- **git opens its attribute files inside unrelated commands, and a FIFO there blocks them.** Measured with git 2.55.0 and git-lfs 3.6.1, temp repos, `LC_ALL=C`, `GIT_LITERAL_PATHSPECS=1`, a stat-dirty worktree (tracked files `touch`ed), a FIFO at the root `.gitattributes`, each command under `timeout 1`. code-git probes them first (`ATTRIBUTE_FREE`, `assertAttributesReadable` in `src/git/attributes.js`; [docs/lfs.md → Known limitations](../../docs/lfs.md#known-limitations)).
  - **Open order and flags** (`strace -f -e openat` of `status`): `/etc/gitattributes`, `core.attributesFile` (unset: `$XDG_CONFIG_HOME/git/attributes`, else `~/.config/git/attributes`), the root `.gitattributes`, `.git/info/attributes`, then `<dir>/.gitattributes` lazily, only for the directories whose files git diffs, hashes or writes. None uses `O_NONBLOCK`. Only the in-tree files use `O_NOFOLLOW` (git ≥ 2.32): there a symlink → FIFO or → `/dev/zero` fails `ELOOP` and git warns and goes on, a socket fails `ENXIO`, a directory is ignored; so a worktree writer's one weapon is a FIFO (a device node needs `CAP_MKNOD`). `info/attributes` and `core.attributesFile` follow links: a FIFO, a device or a link to one blocks (a link to `/dev/zero` reads forever, CPU-bound).
  - **Block on a root FIFO:** `status`, `diff` of the worktree and `--cached` / tree↔tree with `--numstat` or patch output, `diff-files`, `diff-index HEAD`, `diff-tree --numstat` / `-p`, `log -p` / `--numstat` / `--shortstat`, `show`, `blame`, `format-patch`, `grep <rev>`, `merge-tree --write-tree` with a content merge, `merge`, `cherry-pick`, `revert`, `rebase`, `switch`, `checkout`, `reset --hard` / `--mixed`, `restore --worktree`, `stash apply`, `commit` (even `--allow-empty`, through its index refresh), `update-index --refresh`, `add`, `apply` (`--cached` too), `hash-object -- <path>` / `-w --stdin --path=`, `diff --no-index` content output, `ls-files --eol`, `check-attr`, `git lfs ls-files --json` / `prune`, and **`push` with git-lfs's `pre-push` hook installed**.
  - **Do not block** (1–16 ms each): the subcommands `ATTRIBUTE_FREE` lists, `log` in the forms its predicate accepts (`--format`, `--topo-order`, `--skip` / `--max-count`, `--no-walk`, `-g`, `--grep` / `--author`, `--follow -M --name-status` across a real rename, `-- <path>`), `stash list` / `store` / `drop`, `worktree list`; also `diff --cached --name-only`, `diff-index --cached --quiet`, `diff-tree --name-only`, `diff --no-index --raw`, `hash-object --no-filters`, `hash-object -t tree --stdin`, `lfs version`, `submodule status`, which stay off the list (mixed forms, none hot) and are probed.
  - **`git check-attr -z <attr> -- <path>` is an exact stand-in**: git's one attribute stack opens the same system, global (or XDG default), root and info files, plus the nested files along `<path>`, and blocks on a FIFO in each. ~0.94 ms on a small repo (`rev-parse`: 1.03 ms); 6.9 ms with a 100k-entry index, which it loads. It mirrors git whatever the version (below 2.32 a symlink → FIFO in-tree blocks both).
  - **Nested `.gitattributes` stays residual.** A FIFO at `sub/.gitattributes` blocks `status`, `add` and git-lfs whenever a file under `sub/` is stat-dirty, not `diff -- a.txt` at the root. Covering it would cost a second command per op run: `ls-files -z` plus dirname extraction 57 ms, `check-attr --stdin` with one path per directory 70 ms, at 100k entries / 10k directories on a warm cache (~1.5 MB each way, linear), still blind to untracked directories.
  - **`-c core.attributesFile=/dev/null` is no fix**: it changes what git does (`add` would ignore a global `filter=lfs`).
- **git-lfs opens `.gitattributes` by path in its own process**, after code-git's last command: `assertAttributesWritable` sits just before `lfs track` / `lfs untrack` (narrowing a symlink/FIFO swap's window) but cannot make the check atomic with the write ([docs/lfs.md → Known limitations](../../docs/lfs.md#known-limitations)).
- **A foreign hook at one of git-lfs's hook names makes it install none** of the four, keep that hook and exit 0.
- **`GIT_LITERAL_PATHSPECS=1` breaks `git lfs pull` silently**: it checks nothing out and exits 0. The LFS ops run `git --no-literal-pathspecs lfs …` (git sets the variable to 0 for git-lfs and the git it runs); `subcommandOf` skips that flag when naming the subcommand.
- **`ls-files --json` answers `{"files": null}`** for no LFS files, not `[]`. Its 3.3.0 fields are `name, size, checkout, downloaded, oid_type, oid, version`; the parser reads `name, size, oid, downloaded` only.
- **`git lfs version` without git-lfs expands a repo's `alias.lfs`** (a `!` alias runs a shell command — on a read). git looks for `git-lfs` before aliases, so an installed git-lfs is never shadowed; the probe runs `git -c alias.lfs= lfs version`, and git's `expansion of alias 'lfs' failed; '' is not a git command` (exit 1, git 2.39 and 2.55) means absent. Without the override and without an alias, git says `'lfs' is not a git command`.
- **A path or `file://` remote needs no LFS server**: git-lfs's standalone file transfer serves it. Tests and seeds push objects with `git lfs push --all origin` and clone smudge-skipped (`GIT_LFS_SKIP_SMUDGE=1`) to get pointer files.
- **Tests write `filter.lfs.*` into the temp HOME's gitconfig** (`lfsFilters` in `tests/_lfs.js`, `GIT_CONFIG_GLOBAL` from `hermeticEnv`), never into the developer's global config.
- **A System without git-lfs but with `filter.lfs.required=true`** makes git itself fail (`git status` cannot run the required filter): the "absent" worlds (`strippedWorld`, `seedLfs({absent: true})`) use a repo and HOME without LFS filter config.
- **Removing git-lfs from a fake System**: `cc.state.inheritedEnv = {PATH: <dir>}` with only a `git` symlink in `<dir>`. git finds its own helpers through its exec path, not PATH; git-lfs is found through PATH. A stub `git-lfs` script there fakes an older version.

## Hooks

- **git sends a hook's stdout to stderr, except pre-push's**: a pre-push hook's stdout goes to git's stdout, which `push --porcelain` output shares. A push that failed as a whole reported no ref there, so `push` (`src/git/remote/push.js`) puts that stdout before git's stderr on a `GIT_FAILED` refusal (`tests/hooks.test.js` pins it); the activity entry records stderr only.
- **post-checkout runs after the switch**: when it fails, `branch.checkout` refuses `GIT_FAILED` but HEAD has moved.
