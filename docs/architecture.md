# Architecture

## Module map

**Backend** (`src/`, plain ESM; `server.js` is the entry):

| Module | Responsibility |
|---|---|
| `server.js` | `start({port, distDir, …})`: builds the app, listens on `127.0.0.1`, answers parser-rejected requests (`clientError`) with the CSP. Exports `start`, `createApp`, `CSP`, `DEFAULT_PORT`; autostarts only when run directly |
| `src/app.js` | `createApp({distDir, ops?, activity?, journal?})`: wiring only — headers → `/health` → `/api` (JSON check, body parser, feature routes, API 404) → UI → 404 → error handler. `ops`/`activity`/`journal` are injectable for tests |
| `src/http/security.js` | `CSP`, the headers middleware, `requireJson` |
| `src/http/static.js` | `serveDist(distDir)`: the `ASSET_RE` allowlist, `inside()` realpath check, 503 while unbuilt |
| `src/http/route.js` | `route(fn)`: a throw becomes a refusal response; `sendError` |
| `src/refusals.js` | `Refusal` and `HTTP_STATUS` (the code table) |
| `src/mask.js` | `maskUrl`: a url's password shown as `***`, the one masking used for every url the browser gets (remote.list, the remote ops' undo records, `resolvedUrl`) and activity argv; `isMaskedUrl`: a url whose password is that mask (remote.add / remote.edit refuse it); `maskUrls` / `maskDeep` for text and refusal bodies. One hand-written scanner from each `://` (`nextUrl`), linear in the input: no regex looks for a scheme's start |
| `src/conductor/fetch.js` | `ccFetch`: `CONDUCTOR_URL`, per-attempt deadline, caller abort → `CANCELLED`, connection-only retry |
| `src/conductor/cc.js` | `projects()`, `worktrees(project)` |
| `src/conductor/exec.js` | `exec(target, argv, opts)`: cc exec form A + the refusal map; `CC_EXEC_CAPS` |
| `src/git/validate.js` | Pure input checks: `assertTarget` (with `sub`: `submoduleChain`), `assertRefName`, `assertRev`, `OID_RE` / `assertOid` (the one full-oid check, the diff sources use it too), `assertPath`, `assertSubpath` |
| `src/git/limits.js` | `LIMITS`: per-kind timeout / output cap, stderr cap, activity ring size, cc read deadline |

| `src/git/ops/undo.js` | `undo.state`, `undo.undo`, `undo.redo` |
| `src/git/ops/history.js`, `src/git/parse/history.js`, `src/git/history/limits.js` | `history.file`, `history.blame`, `history.reflog`, `history.paths` ([history](history.md)); their pure parsers (`parseFileHistory`, `parseBlame`, `parseReflog`); `HISTORY_LIMITS` |
| `src/git/ops/repo.js` | `repo.summary` |

**Op definition rules** (enforced by `buildRegistry` at load; a violation throws):

- `name` matches `^[a-z]+\.[a-zA-Z]+$` and is unique.
- `kind` is `'read'` or `'write'`.
- `cancellable`, when given, is a boolean; it defaults to `kind === 'read'`. A write sets `cancellable: true` only where aborting mid-command cannot leave the repo half-changed, and its card states why: `remote.fetch` (atomic ref updates, gc off, no index or worktree), `remote.push`, `tag.push`, `tag.deleteRemote`, `branch.deleteRemote` (atomic remote ref updates). `remote.pull`, `merge.start`, `rebase.start`, `rebase.interactive`, `conflict.save`, `conflict.take`, `head.continue`, `head.skip` and `head.abort` are not: an abort mid-merge or mid-rebase would.
- `undo`, when given, is a function, and only on a write ([undo → Registering an op](undo.md#registering-an-op)).
- `journal`, when given, is `'neutral'`, on a write without `undo`.
- `params(raw)` validates and returns typed params or throws a `Refusal`; `run(git, params, {target, journal})` returns JSON. `target` is the call's validated `{project, worktree, sub?}` (worktree `null` = main checkout; `sub` a submodule chain), for an op that names its output after the checkout (`diff.patch`); `journal` is the undo journal, read only by the `undo.*` ops; git still runs only through `git`. `git(args, opts)` is `runGit` bound to the call's context. One op may run several commands; each gets its own activity entry with the call's `opRunId`. For a write, the route opens the call's run first (`activity.openRun`), counts each `git` call through `run.track`, and calls `run.end()` in a `finally` ([Write op runs](#write-op-runs)).

## Runner pipeline (`runGit`)

1. argv = `['git', ...BASE_ARGS, ...subArgs(target), ...args]`. `BASE_ARGS` disables the pager, colour, path quoting, fsmonitor and submodule recursion (`submodule.recurse=false`: a repo's `true` would make a discard of a submodule row discard the submodule's own uncommitted work; only `submodule update`/`sync` pass `--recursive`), and pins `--work-tree=.`: the checkout cc runs the command in is the working tree, whatever the repo's `core.worktree` says (it resolves after `-C`). For a target with a submodule chain, `subArgs` adds `-C <chain> --git-dir=.git` (the explicit git dir stops git walking up from a submodule not cloned yet to the parent: [submodules → Addressing](submodules.md#addressing)); before such an op runs, the route's containment preflight (`assertInsideCheckout`: top levels and each level's git dir) costs three reads plus two per chain level. A bare repository then looks like a working tree of its own files, so `repo.summary` (before `status`) and every write check first whether the git dir is the working tree itself — `rev-parse --git-dir` printing exactly `.`, no path parsed — and refuse `BARE_REPO` (`src/git/worktree.js`: `isBare`, `assertWorktree`). Never `core.bare`: the repository sets it (directly or through an `[include]`), so a bare repo saying `false` would pass.
2. env = `BASE_ENV` + (`READ_ENV` for reads) + the op's env. An op's env naming a protected variable (`isProtectedEnv`: the names in `PROTECTED_ENV` — `GIT_TERMINAL_PROMPT`, `GCM_INTERACTIVE`, `GIT_ASKPASS`, `SSH_ASKPASS`, `SSH_ASKPASS_REQUIRE`, `GIT_LITERAL_PATHSPECS`, `GIT_DIR`, `GIT_WORK_TREE`, `GIT_EXEC_PATH`, the trace names in `TRACE_LOCKED` — and every name starting with a `PROTECTED_ENV_PREFIXES` entry: `GIT_SSH` (`GIT_SSH`, `GIT_SSH_COMMAND`, `GIT_SSH_VARIANT`, …) or `GIT_CONFIG`) throws before anything runs or is logged: a code-git bug, answered 500 `INTERNAL`. `GIT_EDITOR` and `GIT_SEQUENCE_EDITOR` stay overridable (an interactive-rebase todo editor, say).
3. A write takes its **project's** lock (worktrees share refs and objects); reads and other projects never wait.
4. The activity entry opens (`running`) with its own `AbortController`, combined with the op's signal.
5. `exec` → cc. The deadline and output cap default from `LIMITS[kind]`.
6. The entry closes with cc's duration, the exit code, the stderr tail, and a status. An exit outside `okExit` (default `[0]`) throws `GIT_FAILED`.

**Non-interactive git.** `BASE_ENV` sets `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`, `GIT_ASKPASS=false`, `SSH_ASKPASS=false` and `SSH_ASKPASS_REQUIRE=never` (cc's local provider merges the System's own environment, whose askpass program git would run despite `GIT_TERMINAL_PROMPT=0` and wait on until the timeout), `GIT_EDITOR=false`, `GIT_SEQUENCE_EDITOR=false` (an accidental editor launch fails instead of hanging), `GIT_LITERAL_PATHSPECS=1`, `LC_ALL=C` (git's own messages only — repo-specific matching such as `NOT_A_REPO` relies on it), and `TRACE_OFF` (`src/git/runner.js`) over the System's environment — which also beats a `trace2.*Target` in its global config: every trace and trace2 switch `0` (git reads each by value), `GIT_TRACE2_CONFIG_PARAMS` and `GIT_TRACE2_ENV_VARS` empty (inert because every trace2 target is off: an empty one does not override a list in git config), `GIT_TRACE_REDACT` and `GIT_TRACE2_REDACT` `1` (an empty value would read as false). `GIT_CURL_VERBOSE` is never set — git reads it for presence, so even `0` turns curl's verbose output on (request paths, response headers and cookies) — but an op's env may not set it either (`TRACE_LOCKED`); a System env that sets it is its operator's opt-in, since an exec cannot unset an inherited variable, and the forced `GIT_TRACE_REDACT` and `maskUrls` still keep the Authorization header and url passwords out. Trace output can print a url's userinfo without its scheme, where no mask finds it: `GIT_TRACE`'s `trace: run_command: ssh … user:password@host`, trace2's `child_start` of the same (trace2 redacts only `scheme://` urls) and a `def_param` of a config url; others print request headers. `READ_ENV` adds `GIT_OPTIONAL_LOCKS=0`, so a read never refreshes the index.

**Validation.** No route takes argv or git options. Everything a user names is checked before any exec:

| Input | Check | Then |
|---|---|---|
| target | `assertTarget`: only `project`/`worktree`/`sub` keys; names not `.`/`..` (they would rewrite the cc URL a name is spliced into); `sub` a chain of `submodulePath`s | `{project, worktree}` sent as exec form A, so the System is always the project's own; `sub` becomes `-C … --git-dir=.git` |
| a ref to create | `assertRefName` (`git check-ref-format --allow-onelevel` rules, no leading `-`) | — |
| an object id | `assertOid`: 40 or 64 lowercase hex | sent on stdin or after `--end-of-options` |
| a revision | `assertRev`: no leading `-`, whitespace or control characters | placed after `--end-of-options` where the subcommand parses options |
| a path | `assertPath`: relative, no `..` segment, NUL or backslash; a leading `-` is allowed | always after `--`; `GIT_LITERAL_PATHSPECS=1` makes `:(glob)`, `*` and friends literal |
| a `-C` subpath | `assertSubpath`: `assertPath` + no leading `-`; a submodule path also `submodulePath` (no empty/`.` segment, no `.git` alias) | — |

**No process or filesystem access in `src/`** except `src/http/static.js` reading `frontend/dist`: git runs only through cc. A test (`exec.test.js` guard) enforces it.

## Diff

- **Paging unit = one file.** `diff.files` is one `--raw --numstat -z` command under `DIFF_LIMITS.listMaxOutputBytes`; past it the whole list is refused (`OUTPUT_TOO_LARGE`), never shown partial. Each file's hunks are a separate `diff.file` under `fileMaxOutputBytes`.
- **Pinned pair.** `diff.files` returns the resolved `pair`; the UI loads every file with `{kind: 'pair', ...pair}`, so a moving HEAD or ref cannot mix two commits in one view. Work-in-progress sides are refetched by Refresh or a new `openDiff`.
- **Config that reshapes diff text is overridden on every command** (`DIFF_CONFIG`, `DIFF_FLAGS`, `FORMAT_PATCH_FLAGS`); the list of keys and their overrides: [wiki: gotchas/diff-parsing](../.wiki/gotchas/diff-parsing.md). The test fixture (`tests/_diffRepo.js`) sets all of them. **Not neutralised:** `filter.<driver>.clean` / `.process` still run when a diff reads a worktree file (worktree sides and untracked `--no-index`); git has no diff flag to disable them, and `git status` (`repo.summary`) already runs them for tracked files.
- **Contract for later cards.** `openDiff(target, source, {path})` opens a diff (the graph's details panel and multi-select). `FileDiff` → `Hunk` (id = `header`) → `DiffLine` is the model per-hunk/line staging addresses as `(hunk index, line index)`; a patch rebuilt from it needs `whitespace: 'none'` ([protocol](protocol.md#difffile-read-cancellable)).
- **UI state.** `diffStore` is keyed by `tabKey`; a list load bumps `generation`, and a file answer for an older generation is dropped. `fileKey` = path + context + whitespace, so switching mode or context refetches only what is missing. Inline, Split and File view request `context: 'full'`; Hunk mode the chosen context.
- **Line staging in the views.** `Cell` carries its `(hunk, index)`; a hunk row its `hunk`. `UnifiedView` / `SplitView` take an optional `staging: StagingView` (`CodeLine.tsx`: `selected`, `onToggle`, `hunkActions`); only `DiffPanel` builds it, and only when `canPartial`. The request's `context` is `contextFor(prefs)`, the context the hunks were loaded with.
- **Rows** render as `div`s in chunks of `CHUNK_ROWS` with `content-visibility: auto` (`Chunked` in `features/diff/CodeLine.tsx`); a change block's first row carries `data-change-index`, a search match `data-match` / `data-match-current`.

### Rendering safety: highlighting

- `highlight/prismManual.ts` sets `globalThis.Prism = {manual: true, …}` and is the first import of `highlight/prism.ts`, so Prism never highlights `language-*` elements on load. `prism.ts` is reached only by `import()` (its own chunk).
- Only `Prism.tokenize` is used. `highlightLines` flattens the token tree to `{text, cls}` segments; `cls` comes only from the fixed `TOKEN_CLASS` map; `CodeLine` renders them as React text. `guards.test.ts` refuses `Prism.highlight`, `highlightElement` and `highlightAll` anywhere.
- Bounded per file side: past `HIGHLIGHT_MAX_LINE_CHARS`, `HIGHLIGHT_MAX_LINES` or `HIGHLIGHT_MAX_SIDE_CHARS` the side is plain and the tokenizer is not called. Word emphasis is bounded by `WORD_DIFF_MAX_CHARS` / `WORD_DIFF_MAX_TOKENS`.
- A patch download is a local `blob:` URL of `text/x-diff` bytes, clicked and revoked, never rendered; its name is the backend's sanitized `filename`. Only `lib/download.ts` builds object URLs or download links (guard test).

## Staging and committing

- **Byte-exact selection patches.** The line ops read the file's diff as latin1 (one character per byte), so CR, non-UTF-8 bytes and git's path quoting pass through unchanged; only the comparison with the request decodes UTF-8, the way `diff.file` decoded what the UI showed. Rules: [protocol → Stage selection](protocol.md#stage-selection-stagestagelines-stageunstagelines-stagediscardlines-write).

- **Residual risks.** `commit.gpgSign=true` runs the configured signer; a signer that cannot sign (no key, or no pinentry: the exec has no tty) fails at once as `GIT_FAILED` — verified with gpg 2 + pinentry-curses (`RUN_REAL_GPG=1` test in `tests/ops-commit.test.js`). A signer that waits forever would run until the write timeout. Commit messages are assumed UTF-8 (`i18n.commitEncoding` is not read).
  - **`git apply --index` writes through an untracked symlink.** It checks a path's leading directories against the index only, so with an untracked `link → /outside` a patch creating `link/x` writes `/outside/x` (exit 0). Plain `git apply` (worktree) lstat-checks and refuses ("beyond a symbolic link"); `--cached` writes only the index. So no op passes `git apply --index`: `patch.apply` offers worktree and index only. An op whose git command runs it internally (`stash push -- <paths>`) or that writes paths a stash names refuses every path behind an untracked symlink or file first (`PATH_BLOCKED`, `src/git/stash/guard.js`); a later op in the same position (cherry-pick by patch) does the same. (`git stash apply --index` is another option: it restores a stash's staged part.)
  - **Stash** (details: [stash](stash.md)):
    1. `git stash push -- <paths>` and `--staged` restore the worktree with `diff-index -p --cached HEAD | apply --index -R` inside git (the `--index` write-through above). git 2.55 refuses every write-through case the probe tests try (`tests/stash-git-probes.test.js`: "beyond a symbolic link", "pathspec did not match", "untracked working tree files would be overwritten"), but `--staged` fails *after* creating the stash, and an apply with the path still in the index replaces the symlink with a real directory. Every stash op that writes the worktree refuses `PATH_BLOCKED` first, whatever git would do: an untracked or ignored entry (symlink or file) at a proper leading directory of the paths it writes — for a save, the named paths and what they expand to — and, for the two ops that write one named file (`applyFile`, `pushLines`), a directory or a link to a directory at the file itself. A symlink to a file at the final component is left to git, which replaces or deletes the link (or refuses "wrong type") and never writes through it. Not covered: a case-insensitive filesystem whose `core.ignorecase` is false.
    2. The `PATH_BLOCKED` and untracked-collision gates are check-then-act: a symlink or file created between the gate and git's own run is not caught. With `core.ignorecase` the guard lists the leading directories and also each one's parent (a parent's listing names a fully untracked directory `u/` and nothing under it) — the parent listing is the whole repo's untracked set when a path is top-level, which grows with the repo instead of the request (capped: `OUTPUT_TOO_LARGE` past `STASH_LIMITS.pathsMaxOutputBytes`).
    3. `stash.pushLines`' temporary index: **Temporary indexes** below.
    4. Drops address `stash@{n}`, which other sessions can move: `dropVerified` detects a wrong drop and stores that entry back, at the top.
    5. `stash push -u` with an untracked nested repository follows git's own behaviour.
    6. git's apply is not atomic across a stash's tracked and untracked parts: the untracked part is restored after the merge, file by file. The collision gate makes the common failure (a file already there) refuse first.
    7. A save claims its stash by base and subject among the entries newer than the tip read before it: another session saving a stash at the same base with the same subject at the same moment, or dropping that tip meanwhile, makes it `unverified` (no undo). An undo applied later still trusts that an oid the save named is this save's.
    8. git resets the index before a `stash apply --index` merge and leaves it unstaged when the merge refuses to start; code-git reads the saved index tree back (only then: never after a conflicted merge, whose unmerged index git kept), which does not restore stat data, intent-to-add or skip-worktree bits.

### What each destructive op destroys

What an op overwrites or deletes, and whether git can give it back. The branch, tag and HEAD ops: [refs → Undo record](refs.md#undo-record) (their `result.undo` and the table there). Which ops undo and redo actually run: [undo → Per-op plans](undo.md#per-op-plans).

| Op | Destroys | Recoverable from git |
|---|---|---|
| `stage.files`, `stage.unstageFiles` | The previous index entries of those paths | Yes: HEAD and the worktree still hold both sides |
| `stage.discardFiles` — tracked | The worktree content of those paths (returned in `result.tracked`) | Until gc: `undo.discard.snapshot`, a commit of their worktree content taken before the discard |
| `stage.discardFiles` — untracked | The files (returned in `result.untracked`) | Until gc: the same snapshot |
| `stage.stageLines`, `stage.unstageLines` | Nothing outside the index | Yes |
| `ignore.add` | With `stopTracking`, the index entries of the matching files (returned in `result.untracked`); the files stay | Yes: `git add` re-tracks them; `.gitignore` gains one line |
| `files.restore` | That path's index entry and worktree content (an untracked symlink in the way is replaced by a directory) | The index entry yes (HEAD); uncommitted worktree content no |
| `patch.apply` | Nothing it does not change; atomic | Yes: the same patch applied with `-R` |
| `commit.create` with `amend` | Nothing: HEAD moves to the new commit | Yes: the replaced commit stays in the reflog (`HEAD@{1}`) |
| `stage.discardLines` | Exactly the lines of the applied patch, from the worktree | Yes, by the op itself: `result.patchB64` applied forward (`git apply`) restores them |
| `stash.push`, `stash.pushLines` | The saved changes leave the worktree (and the index, unless `keepIndex`); `includeUntracked` removes the untracked files | Yes: the stash holds them; their undo writes back the recorded state (`undo.worktreeState`) or the lines (`undo.removedPatch`) |
| `stash.apply` | Nothing it does not merge into; git refuses over local changes | The merge into the worktree, no: `undo` is empty |
| `stash.pop` | As apply, then the stash entry | Clean: yes, by its undo (`undo.worktreeState` and `restore: 'store'`; the entry back at `stash@{0}`); with conflicts: the entry is kept, the merge no |
| `stash.applyFile` | Nothing it does not change; atomic | Yes: `undo.worktreePatch` applied with `-R` |
| `stash.drop` | The stash entry | Until gc: `stash store --message=<old> <oid>` (`restore: 'store'`) |
| `stash.rename` | The original entry (after the renamed copy is stored) | Yes: `restore: 'drop'` the copy, `restore: 'store'` the original |
| `stash.branch` | As pop, after creating and switching to a branch | Clean: yes, by its undo (`undo.refs`, `undo.head`, `undo.worktreeState` with `mid`); with conflicts: the ref/HEAD move yes, the merge no |
| `conflict.save` | The worktree content of that path (the conflict markers git wrote, or an earlier resolution) | The markers yes, by re-running the merge's checkout of the path (`checkout -m -- <path>`, while the stages are there); hand edits no |
| `conflict.take` | Those paths' unmerged stages, any resolution in their worktree files, and — for a side that deleted it — the file | The stages no (they are the operation's; aborting it restores the pre-operation state); the deleted file's other version stays in its stage's blob until gc |
| `rebase.interactive` with drops | The dropped commits leave the branch | Yes until gc: the branch's old tip (`undo.refs[].old`) still holds them |

## Long ops, cancel and paging

- cc's exec buffers output and has no progress channel. An op stays pending up to its `timeoutMs`; its activity entry is pushed as `running` first, so the UI shows an elapsed timer and, when the op is cancellable, **Cancel**.
- Cancel aborts the request to cc; cc kills the command when its client disconnects. The HTTP client of `POST api/ops/:name` going away aborts the op the same way — only when the op is cancellable. A non-cancellable write keeps running and is logged.
- The fetch deadline is past cc's (`timeoutMs + min(10 s, timeoutMs)`) so cc reports `EXEC_TIMEOUT` first.
- Large reads page by git arguments, never by re-slicing output ([protocol](protocol.md#paging-convention-for-ops-that-list)).

## Activity log

- In memory, per backend process, newest `LIMITS.activityRing` entries; runs are capped the same way, but only ended runs are dropped (a running one stays until it ends, so `writeRunning` never reads a project idle mid-write). **Diagnostic only**: undo, reflog and every other feature derive state from git, never from this log.
- Records what ran (argv, through `redactArgv`: a url's password masked (`src/mask.js`) — by `maskUrl` in git's own options and every argument of a `VALUE_SUBCOMMANDS` command (`src/activity/log.js`: the whole argument is a url or value), by `maskUrls` in any other argument (a commit message keeps its shape): `https://u:***@h/r`; the value of a `git config` write to a `remote.<name>.<var>` key other than `url` / `pushurl` / `fetch` replaced by `***`, the key kept), where, the op's env overlay with secret-looking values redacted, stdin size (never content), the stderr tail (hook output included, decoded with `TextDecoder` `fatal: false`).
- `events` (an `EventEmitter`) feeds the SSE route; the UI refetches on each event.

### Write op runs

- **Why.** A multi-command write (`submodule.remove`: rm, deinit, …; `submodule.update`: init, clone, checkout; a rebase `remote.pull`: fetch, then rebase) leaves the repository half-done between its commands. A watcher refreshing when a command closes would read that state (a header saying "not a git repository", a detached HEAD mid-rebase). The project lock is per command (`runGit`), so nothing else marks the gap.
- **Backend.** `routes/ops.js` opens a run for every write call before the containment preflight, wraps `git` in `run.track` (a call counts from its start, lock wait included, until it settles), and calls `run.end()` in `finally`. The log marks the run `ended` once `end()` was called and no tracked call is pending — so a `Promise.all` whose first command failed still waits for a sibling queued on the lock ([protocol → Activity](protocol.md#activity)).
- **UI.** `state/settledWrites.ts`, over `activityStore.runs`: `onSettledWrite(project, match, fn)` calls `fn` once a matching run of the project ended and none of the project's runs is running (overlapping writes: one call, after the last; a run already running at subscribe time is waited for). Its users: the graph's watcher (`watchGraph`: refs, every checkout's summary, pages), the Submodules panel (`useSubmodules`), undo (`useUndo`, this checkout's runs only). `writeRunning(project)` gates the graph's and the Submodules panel's focus refresh (skipped: the run's end refreshes with the same reads) and auto-fetch (`skipReason` → `writing`).
- **Not deferred.** A read the user starts (Refresh, opening a tab, a diff, an op wrapper's own refresh after its answer) and anything changed outside code-git can still meet a write half-done.

## UI state and routing

- No state library: `createStore` + `useSyncExternalStore`. Each feature owns its store; per-checkout state is keyed by `tabKey` (`project + '\0' + (worktree ?? '')`, then `'\0' + path` per submodule chain entry). State derived from refs that a project's worktrees share (branch tracking, the remotes list and busy state) is keyed by `refsKey` (the project, or a submodule tab's own key); graph prefs by `prefsKey` (the bare project name, or the project then `\0<path>` per chain entry).
- Tabs persist under `code-git:tabs` (a row with a malformed `sub` is dropped); the active tab is mirrored into `?project=…&worktree=…&sub=…` (one `sub` per chain entry) with `history.pushState` (which cc's bridge turns into `replaceState`), read on load and on `popstate`.
- Untrusted text (argv, stderr, ref and project names, git messages) renders only as React text children: no raw-HTML API, no `href`/`src`/`style` built from data. `guards.test.ts` scans the sources for both, and for colours that bypass the tokens (literal colours, palette shades, `white`/`black`, non-`var()` arbitrary values) outside the copied `components/ui/`.
- Palette: `cc-theme-fallback.css` is a one-time snapshot of cc's tokens in `@layer base`; embedded, cc's unlayered `/pluginTheme.css` wins. `palette.test.ts` pins its values and the `@theme inline` block from cc's `docs/plugin-ui.md`.
