# Visual-verification harness

Built on the shared code-playwright helpers (`withPage`, `bootServer`), resolved by `resolve.mjs` from
`$CC_PROJECTS_ROOT/.plugins/code-playwright/browser.mjs`. A shell that code-conductor did not spawn must export
`CC_PROJECTS_ROOT` (the absolute projects root) first.

Build the UI first: `npm install` (or `npm run prepare`) so `frontend/dist` exists. Screenshots land in the gitignored `out/`.

## `live.mjs` — read-only against a live cc

- Boots this checkout's backend with `CONDUCTOR_URL` set (`bootServer` picks the free port and passes `PORT`) and drives only the UI's read path: the picker, `repo.summary` (`git status` with `GIT_OPTIONAL_LOCKS=0`) and the reads an open tab makes (`graph.*`, `branch.tracking`, `remote.list`, the Changes panel's `diff.files` and `commit.*` reads). The script fails if the page posts any op the registry (`OPS` in `src/git/ops/index.js`) does not call a read, or if any non-read command lands in the activity log.
- Never calls a write route, never registers, rescans or enables the plugin in cc.
- Refuses to run without `CONDUCTOR_URL`, and checks that `$CONDUCTOR_URL/api/health` answers `"app":"code-conductor"`.
- Default checkouts: `code-git`, `code-git/c1-foundation`, `test`, `test/review-demo`; name others as arguments.
- Asserts: the picker lists exactly the names of `GET $CONDUCTOR_URL/api/projects`; every `isGitRepo === false` row is disabled; each checkout's header loads without an error and shows HEAD as a branch, or the detached or unborn badge (for a worktree on a branch, whether it is the branch cc recorded is printed as a note, not required: HEAD may have moved since); the activity panel has a `status --porcelain=v2` entry with exit 0 per checkout; Ctrl+1 / Ctrl+2 switch tabs; each checkout's toolbar shows Fetch, Pull and Push; each project's `remote.list` answered (`git remote` exit 0). On a checkout whose project is on a non-local System (e.g. `test` on `docker`/`cc-box`) whose HEAD has an upstream on a remote, it calls `remote.peek` (`git ls-remote`, a read) through the backend: it must answer ok, or `REMOTE_AUTH_FAILED` / `REMOTE_UNREACHABLE` with a readable message, within `NETWORK_LIMITS.timeoutMs` — the System's own credentials, never a prompt; without an upstream it prints a note. On the same checkouts it calls `commit.state` (its `cat-file --batch-check` takes the pseudo-ref names on stdin, through cc's stdin path on that System): it must answer `merging`, `operation: null` and `conflicts: []` — the live checkouts have nothing in progress. Screenshots: `out/live/`.
- Run for the remotes card: `CONDUCTOR_URL=… node harness/playwright/live.mjs test code-git`.

**Finding `CONDUCTOR_URL` from a cc worker session.** The session's environment has no `CONDUCTOR_URL`, but its Claude process was started with an `--mcp-config` naming cc's MCP URL. Walk up from the shell's own process and take the origin, then confirm it:

```bash
p=$$; while [ "$p" -gt 1 ]; do u=$(tr '\0' ' ' < /proc/$p/cmdline | grep -oE '"url":"http://127\.0\.0\.1:[0-9]+' | head -1 | sed 's/"url":"//'); [ -n "$u" ] && break; p=$(awk '/^PPid:/{print $2}' /proc/$p/status); done; echo "$u"
curl -s "$u/api/health"   # → "app":"code-conductor"
```

Other cc instances (scratch ccs) may listen on other ports: never pick one by port scan.

## `live-history.mjs` — read-only history check

- Same refusals as `live.mjs`; find the URL as above. Opens the checkout by URL and waits for its graph (the palette's history commands need HEAD).
- Through the palette: **File history…** of the first path `history.paths` lists at HEAD (its history has at least one commit, the viewer shows its change without an error), its **Blame** (lines, or the binary-file notice), and the **Reflog** of HEAD (its entry count printed: a System's clone may keep no reflog).
- Fails if the page posts an op whose registry `kind` is not `read` (`undo.state` and the `history.*` ops are reads), or if a non-read command lands in the activity log; requires `history.file` exit 0 and a `history.reflog` run on the System. Screenshots `out/live/history-*.png`. Never Rescans, Enables or mutates anything.

## `live-graph.mjs` — read-only graph measurement

- Same refusals as `live.mjs`: no `CONDUCTOR_URL`, or `$CONDUCTOR_URL/api/health` not answering `"app":"code-conductor"`, stops it. Find the URL as above.
- Opens the checkout by URL (`?project=…`), so the picker is never used, and scrolls its graph to the end of the snapshot.
- What runs: `repo.summary` of each of the project's cc checkouts, the `graph.*` ops, `branch.tracking` and `remote.list` — all `kind: 'read'` with `GIT_OPTIONAL_LOCKS=0` — plus cc's project and worktree listings. The script fails if the page calls any other op or any non-read command lands in the activity log.
- Never Rescans, Enables or restarts anything.

## `live-submodules.mjs` — read-only submodule check

- Same refusals as `live.mjs` (no `CONDUCTOR_URL`, or `$CONDUCTOR_URL/api/health` not answering `"app":"code-conductor"`); find the URL as above. Opens the checkout by URL, never through the picker.
- Fails if the page calls any op whose registry `kind` is not `read`. Never Rescans, Enables, seeds or mutates the project.
- Always asserts: the Submodules panel renders without an error ("No submodules" for an empty list) and the activity panel shows `config -f .gitmodules` with exit 0 or 1; then `?project=<p>&sub=no-such-sub` shows `SUBMODULE_NOT_POPULATED` in the header, and its activity entry (labelled `<p> › no-such-sub`) shows `-C no-such-sub --git-dir=.git rev-parse --show-toplevel` with exit 128 — the submodule prefix reached the project's System through cc's form-A exec. Screenshots `out/live/submodules-*.png`.
- When `submodule.list` returns a cloned, unblocked entry it also opens it (`repo.summary` loads, the graph's first page loads); otherwise it prints `SKIP: <p> has no populated submodule — open-as-repo not checked on a non-local System` and exits 0. In that tab it then lists the submodule's own submodules and opens the first cloned, unblocked one two levels deep (`?project=<p>&sub=<level 1>&sub=<level 2>`): the breadcrumb names both ancestors, HEAD shows with no error, the graph's first page loads, `repo.summary` and `commit.state` answer 200, and the preflight's `-C <level> --git-dir=.git rev-parse --absolute-git-dir` ran with exit 0 at both levels — the git-dir check passing on a non-local System. Without a nested entry it prints `SKIP: <p> › <level 1> has no populated submodule — the two-level chain not checked on a non-local System`, keeping the first-level checks.
- **Seed shape that turns both SKIPs into checks** (made on the live System, never by the script): in `test`'s main checkout (`/app` on cc-box), submodule `vendor/live-sub` (name `live-sub`, url `/srv/git/live-sub.git`), committed; inside it, submodule `deps/inner` (name `inner`, url `/srv/git/inner.git`), committed in live-sub's repository; both cloned with `git submodule update --init --recursive` run there, so inner's git dir is `/app/.git/modules/live-sub/modules/inner`. Each needs at least one commit. Seeding a local-path url needs `-c protocol.file.allow=always` on those git commands. The script needs no network, and no `protocol.file.allow` anywhere; a later **Update** from the UI of such a submodule needs `protocol.file.allow=always` in cc-box's global git config (never the repository's: code-git refuses repo-scope `protocol.*`).
