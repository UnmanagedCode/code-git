# Visual-verification harness

Built on the shared code-playwright helpers (`withPage`, `bootServer`), resolved by `resolve.mjs` from
`$CC_PROJECTS_ROOT/.plugins/code-playwright/browser.mjs`. A shell that code-conductor did not spawn must export
`CC_PROJECTS_ROOT` (the absolute projects root) first.

Build the UI first: `npm install` (or `npm run prepare`) so `frontend/dist` exists. Screenshots land in the gitignored `out/`.

## `live.mjs` — read-only against a live cc

- Boots this checkout's backend with `CONDUCTOR_URL` set (`bootServer` picks the free port and passes `PORT`) and drives only the UI's read path: the picker, `repo.summary` (`git status` with `GIT_OPTIONAL_LOCKS=0`) and the reads an open tab makes (`graph.*`, `branch.tracking`, `remote.list`). The script fails if the page posts any op the registry (`OPS` in `src/git/ops/index.js`) does not call a read, or if any non-read command lands in the activity log.
- Never calls a write route, never registers, rescans or enables the plugin in cc.
- Refuses to run without `CONDUCTOR_URL`, and checks that `$CONDUCTOR_URL/api/health` answers `"app":"code-conductor"`.
- Default checkouts: `code-git`, `code-git/c1-foundation`, `test`, `test/review-demo`; name others as arguments.
- Asserts: the picker lists exactly the names of `GET $CONDUCTOR_URL/api/projects`; every `isGitRepo === false` row is disabled; each checkout's header loads without an error and shows HEAD as a branch, or the detached or unborn badge (for a worktree on a branch, whether it is the branch cc recorded is printed as a note, not required: HEAD may have moved since); the activity panel has a `status --porcelain=v2` entry with exit 0 per checkout; Ctrl+1 / Ctrl+2 switch tabs; each checkout's toolbar shows Fetch, Pull and Push; each project's `remote.list` answered (`git remote` exit 0). On a checkout whose project is on a non-local System (e.g. `test` on `docker`/`cc-box`) whose HEAD has an upstream on a remote, it calls `remote.peek` (`git ls-remote`, a read) through the backend: it must answer ok, or `REMOTE_AUTH_FAILED` / `REMOTE_UNREACHABLE` with a readable message, within `NETWORK_LIMITS.timeoutMs` — the System's own credentials, never a prompt; without an upstream it prints a note. Screenshots: `out/live/`.
- Run for the remotes card: `CONDUCTOR_URL=… node harness/playwright/live.mjs test code-git`.

**Finding `CONDUCTOR_URL` from a cc worker session.** The session's environment has no `CONDUCTOR_URL`, but its Claude process was started with an `--mcp-config` naming cc's MCP URL. Walk up from the shell's own process and take the origin, then confirm it:

```bash
p=$$; while [ "$p" -gt 1 ]; do u=$(tr '\0' ' ' < /proc/$p/cmdline | grep -oE '"url":"http://127\.0\.0\.1:[0-9]+' | head -1 | sed 's/"url":"//'); [ -n "$u" ] && break; p=$(awk '/^PPid:/{print $2}' /proc/$p/status); done; echo "$u"
curl -s "$u/api/health"   # → "app":"code-conductor"
```

Other cc instances (scratch ccs) may listen on other ports: never pick one by port scan.

## `live-graph.mjs` — read-only graph measurement

- Same refusals as `live.mjs`: no `CONDUCTOR_URL`, or `$CONDUCTOR_URL/api/health` not answering `"app":"code-conductor"`, stops it. Find the URL as above.
- Opens the checkout by URL (`?project=…`), so the picker is never used, and scrolls its graph to the end of the snapshot.
- What runs: `repo.summary` of each of the project's cc checkouts, the `graph.*` ops, `branch.tracking` and `remote.list` — all `kind: 'read'` with `GIT_OPTIONAL_LOCKS=0` — plus cc's project and worktree listings. The script fails if the page calls any other op or any non-read command lands in the activity log.
- Never Rescans, Enables or restarts anything.
