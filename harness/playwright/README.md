# Visual-verification harness

Built on the shared code-playwright helpers (`withPage`, `bootServer`), resolved by `resolve.mjs` from
`$CC_PROJECTS_ROOT/.plugins/code-playwright/browser.mjs`. A shell that code-conductor did not spawn must export
`CC_PROJECTS_ROOT` (the absolute projects root) first.

Build the UI first: `npm install` (or `npm run prepare`) so `frontend/dist` exists. Screenshots land in the gitignored `out/`.

## `live.mjs` — read-only against a live cc

- Boots this checkout's backend with `CONDUCTOR_URL` set (`bootServer` picks the free port and passes `PORT`) and drives only the UI's read path: the picker, `repo.summary` (`git status` with `GIT_OPTIONAL_LOCKS=0`) and the reads an open tab makes (`graph.*`, `branch.tracking`, `remote.list`, the Changes panel's `diff.files` and `commit.*` reads). The script fails if the page posts any op the registry (`OPS` in `src/git/ops/index.js`) does not call a read, or if any non-read command lands in the activity log.
- Never calls a write route, never registers, rescans or enables the plugin in cc.
- Refuses to run without `CONDUCTOR_URL`, and checks that `$CONDUCTOR_URL/api/health` answers `"app":"code-conductor"`.
- Default checkouts (`DEFAULT_PROJECTS` in `live.mjs`): `code-git` and `test`, each followed by its first worktree by `worktreeName`, as `GET $CONDUCTOR_URL/api/projects` lists them at run time; it prints `checkouts: …` first. A default project the picker would disable (missing from cc, `degraded`, `systemUnreachable`, `gitRefusal`, or `isGitRepo === false`) is skipped with `note: <name> skipped: <reason>`. Name others as arguments (`project[/worktree] …`).
- Refusals before booting: a named checkout cc does not list, or whose project the picker would disable → `live: <name> is not a checkout in cc (<reason>)`, the reason being `no such project`, the same disable reason a skipped default prints, or `<project>'s worktrees: …`; nothing openable → `live: NO_CHECKOUTS: …`. A worktree that leaves cc between the selection and its turn to open is skipped (`note: <name> skipped: no longer in cc`) and later checks cover only the checkouts that opened (`NO_CHECKOUTS` if none did; Ctrl+2 is checked only with two tabs open).
- Asserts: the picker lists exactly the names of `GET $CONDUCTOR_URL/api/projects`; every `isGitRepo === false` row is disabled; each checkout's header loads without an error and shows HEAD as a branch, or the detached or unborn badge (for a worktree on a branch, whether it is the branch cc recorded is printed as a note, not required: HEAD may have moved since); the activity panel has a `status --porcelain=v2` entry with exit 0 per checkout; Ctrl+1 / Ctrl+2 switch tabs; each checkout's toolbar shows Fetch, Pull and Push; each project's `remote.list` answered (`git remote` exit 0, every command `ok`) — read once every `remote.list` request the page sent for that project (two tabs on one project can each send one) has its response and no entry for it is `running`, bounded by `REMOTE_LIST_WAIT_MS` (a timeout states the sent / answered / failed counts and the entries seen); once every request is answered or failed, any failed one fails the run with those counts. On a checkout whose project is on a non-local System (e.g. `test` on `docker`/`cc-box`) whose HEAD has an upstream on a remote, it calls `remote.peek` (`git ls-remote`, a read) through the backend: it must answer ok, or `REMOTE_AUTH_FAILED` / `REMOTE_UNREACHABLE` with a readable message, within `NETWORK_LIMITS.timeoutMs` — the System's own credentials, never a prompt; without an upstream it prints a note.
```bash
p=$$; while [ "$p" -gt 1 ]; do u=$(tr '\0' ' ' < /proc/$p/cmdline | grep -oE '"url":"http://127\.0\.0\.1:[0-9]+' | head -1 | sed 's/"url":"//'); [ -n "$u" ] && break; p=$(awk '/^PPid:/{print $2}' /proc/$p/status); done; echo "$u"

```
